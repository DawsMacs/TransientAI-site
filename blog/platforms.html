Thirteen platforms, one set of answers

2026-10-24 · The TransientAI team · 5 min read

A system that is honest on one machine is not automatically honest on another. The math functions a program calls are allowed to differ in their last bit between platforms, and some of our decisions compare numbers computed with them. So we ran the same exam on thirteen platform configurations and compared the answers byte for byte.

What we ran

Every change to the repository is now built and tested on GitHub's machines on Linux (x86_64 with two different C libraries, aarch64, 32-bit x86, big-endian s390x and riscv64, the last two under emulation), macOS (Apple silicon and Intel), Windows, FreeBSD, NetBSD, OpenBSD, and WebAssembly under a sandboxed runtime. The code that decides what the baby answers was not changed for any of them. We pinned what the baby answers on the reference platform (Linux x86_64): the 4,832 predictions of the static exam, the 787 replies of the adaptive stream with their stated rates, and the scorecard. Every other platform has to reproduce those files exactly. A difference on the reference platform now fails the build; on any other platform it is reported as a finding.

What came out

  • The answers were identical on all thirteen rows. The 150 tests pass on each, the scorecard reads 0.0% wrong on each, and the pinned answers match byte for byte. An older build, made from a commit before our recent work, produced the same files.
  • The math libraries were not identical. A fingerprint of the functions we use (ln, log2, exp, tanh, powi) over the ranges the code reaches differs on macOS, Windows and the BSDs, and on some functions elsewhere. An audit against a higher-precision value says by how much: every ln, log2 and exp result, on every platform, is at most one last-bit step from the correctly rounded value.
  • Our reference is not the most accurate one. On the word-weight logarithm, the Linux library we pinned gets about 0.9% of inputs one step off, FreeBSD and OpenBSD about 7.4%, Windows 0.26%, macOS on Apple silicon 0.003%, and NetBSD and Intel macOS none. A platform that differs from the reference is not therefore wrong.
  • WebAssembly ran with no change to the logic. The same source compiles to a 2 MB file that runs in a sandbox, passes all 150 tests and reproduces the pinned answers. Its logarithms match the Linux reference bit for bit, which fits a program that carries its own math library instead of borrowing the host's. We have only tried one runtime, so we do not claim that holds on every host.
  • DragonFly BSD did not work. Its tests passed, but the program itself crashed at startup inside the standard library of that system's packaged Rust. We dropped the row and said so.

Mistakes along the way

We counted the platform-dependent math calls wrongly twice before a review caught it (32, then "about 13" on the decision path; the real figures are 24 and 11). One of our own tests assumed that a file that exists must contain a memory line, which two BSDs disproved. A green check on a platform does not mean its math is identical, so the page that explains how to run Transient says "CI-tested", never "supported". And the passing tests on DragonFly were a reminder that a test run is not the same thing as the program running.

What this does not show

The machines are virtual machines with one image each, and the two exotic architectures are emulated, not real hardware. The pinned answers cover one exam and one clean stream, plus two streams with a wrong teacher that are re-checked weekly. A difference of one last bit that never flipped a decision in these runs could still do so on an input we did not try, and two places in the code depend on the order of a hash map, which is a known and unfixed source of rare non-determinism. Measured joules exist only on Linux with a readable energy counter; elsewhere the report says it is unavailable.

Try it

How to get, build and run Transient on each of these platforms, and what we did not try, is in the documentation. If it behaves differently on yours, especially if a pinned answer differs, we would like to hear about it: that is the most useful report there is.
